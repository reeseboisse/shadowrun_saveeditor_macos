# macOS SwiftUI Frontend

Two-tier UI per plan §3.1: a rich **Character editor** and a basic, searchable
**World flags** list. Game-neutral save picker that scans all three games even
though Phase 2 only wires up Dragonfall edits — Returns and Hong Kong saves
appear in the list with a "support arrives in Phase 3 / 4" placeholder.

The Swift app drives the Python engine (built in Phase 1) over a JSON-RPC
stdio bridge. Swift owns the UI; Python owns the bytes.

## Prerequisites

- macOS 13+ (deployment target; Xcode 15+ to build)
- Python 3.11+
- [xcodegen](https://github.com/yonaskolb/XcodeGen): `brew install xcodegen`

## Build & run

From the repo root:

```sh
cd macos
make setup     # installs the Python package into ~/.shadowrun-editor/venv
make project   # runs xcodegen → ShadowrunEditor.xcodeproj
make run       # builds and launches the app
```

Or open `ShadowrunEditor.xcodeproj` in Xcode after `make project` and
Cmd-R as usual.

## How the bridge is found

The Swift app looks for a Python interpreter in this order:

1. `$SHADOWRUN_EDITOR_PYTHON` env var (an absolute path)
2. `~/.shadowrun-editor/venv/bin/python3` (what `make setup` creates)
3. `/usr/bin/python3`, then `/opt/homebrew/bin/python3`,
   then `/usr/local/bin/python3`

For (3), the package needs to be importable — either install it system-wide
(`pip3 install -e <repo>`) or set `SHADOWRUN_EDITOR_SRC=<repo>/src` so the
bridge picks it up from PYTHONPATH.

If the bridge can't be started the app shows a setup-instructions panel
instead of crashing.

## Why is App Sandbox disabled?

The editor needs to:
1. Spawn an arbitrary Python interpreter the user picked.
2. Read and write files in another app's Application Support folder
   (each Shadowrun game keeps its saves under
   `~/Library/Application Support/Harebrained Schemes/...`).

Both are constrained or impossible under the App Sandbox without
specialized entitlements (e.g. `com.apple.security.temporary-exception.*`)
that Apple discourages for general-purpose apps. For a personal-use save
editor distributed outside the Mac App Store, ad-hoc signing with the
sandbox off is the simpler path. If you ever want to publish through the
App Store, sandboxing would need to be revisited (likely with a sandboxed
helper app that uses `NSOpenPanel`-granted folder bookmarks).

## Adding a real app icon

Drop a 1024×1024 PNG into
`Resources/Assets.xcassets/AppIcon.appiconset/` and let Xcode generate the
remaining sizes. The `Contents.json` already declares the slots Xcode
expects.
